# 缘分故事屋 💕

一个**零数据库依赖**的匿名相亲故事分享社区。单文件 PHP 后端 + 纯前端页面 + JSON 文件存储，2 核 2G 服务器轻松运行。

- **技术栈**：PHP 7.4+（生产）/ Node.js（本地开发）· 纯 HTML/CSS/JS 前端 · JSON 文件存储
- **无需**：MySQL、任何 PHP 扩展、构建工具、用户注册系统

---

## ✨ 功能特性

**前台（访客）**
- 故事广场：热门/最新 + 13 类标签筛选，分页加载
- 详情弹窗：点赞（本地记忆防连点）、匿名评论、评论回复（两级楼中楼，「回复 @昵称」标注；≥3 条回复默认折叠可展开/收起；发评论/回复局部刷新不跳顶并定位高亮新内容）
- HTML 排版故事：沙箱 iframe 渲染 + 「原文阅读」新窗口打开，样式 100% 原样
- 浏览量防刷：同 IP 24 小时去重
- 标签云（实时计数）、站点统计、关于与合规页面（内容规范/隐私声明/免责声明）

**发布（匿名，无需登录）**
- 13 类单选标签（默认「日常记录」）
- 纯文本 / HTML 双模式编辑，HTML 支持上传本地文件 + 富文本粘贴
- **AI 排版引导弹窗**：切到 HTML 模式自动弹出三步指引 + 可一键复制的提示词模板 + DeepSeek/豆包/小米 MiMo 官网直达（可勾选不再提示）
- 发布后自动跳转预览自己的故事；随机匿名昵称
- 发布者获得删除凭证，可随时删除自己的故事

**站长管理（`/admin.html`，密码保护）**
- 📮 反馈箱：查看/删除网友反馈（含联系方式）
- 📚 故事管理：全部故事按最新排序、按标签筛选、点击预览（沙箱弹窗）、删除任意故事
- 🔑 密码为容器首次启动自动生成的 12 位随机密码（`data/admin_key.txt`），可随时手动修改

**内置安全**
- 内容净化：去 script/事件属性/危险协议/CSS 表达式
- 样式隔离：HTML 故事以沙箱 iframe + CSP 沙箱头渲染，与站点完全隔离
- 管理接口：密码校验（自动生成、无默认值）+ 同 IP 连续失败 5 次锁定 15 分钟
- 写接口限流：按 IP 滑动窗口限制发布/评论/反馈（超限 `429`），防脚本刷屏
- 跨域：接口不返回 `Access-Control-Allow-Origin`，站点为同源部署，第三方站点无法在浏览器里跨域调用管理接口
- 客户端 IP：**默认不信任 `X-Forwarded-For`**。本站前面没有反代，该头可由客户端伪造，
  信任它会让限流和浏览量去重被一个请求头绕过；将来挂了 nginx/CDN 再把
  `api.php` 的 `TRUST_FORWARDED_FOR` 与 `server.js` 的 `TRUST_FORWARDED_FOR` 改成 `true`
- 评论/反馈长度限制；发布者删除凭证（随机 editKey）
- 数据一致性：所有写盘走「临时文件 + `rename` 原子替换」，进程中断不会留下残缺 JSON；
  互斥用**独立的 `.lock` 文件**（`flock` 锁的是 inode，`rename` 之后锁会失效，所以不能直接锁数据文件）；
  PHP 侧「读-改-写」全程持锁（`db_transaction()`），并发下不会丢更新

## 🚀 部署

### 🔑 管理页密码（无需改代码）

管理页 `admin.html` 的密码**不再需要改代码，也没有任何默认密码**：

- **Docker**：容器首次启动时自动生成一个 **12 位随机密码**，写入 `data/admin_key.txt` 并在 `docker logs yuanfen-stories` 里打印一次。
  > 出于安全考虑，`一键部署.bat` 的验证段**不再回显密码**（只提示 `ADMIN-PASSWORD-OK see data/admin_key.txt`）。
  > 需要查看时登录服务器执行 `cat data/admin_key.txt`。
- **宝塔 / 本地 Node**：没有启动钩子，改为**首次调用管理接口时自动生成**同样的随机密码并写入 `data/admin_key.txt`。
- 手动修改：`echo '新密码' > data/admin_key.txt`（改文件立即生效，无需重启）
- ⚠️ 该文件是唯一的管理入口，请妥善保存；已加入 `.gitignore`，切勿提交进仓库

**登录限流**：同一 IP 连续输错 **5 次**密码即锁定 **15 分钟**（返回 `429`），期间即使密码正确也会被拒。防脚本暴力猜密码用；记录写在 `data/admin_guard.json`，删除该文件即可立即解锁。

### 方式一：宝塔面板（推荐，最简单）

1. 宝塔 →「网站」→ 添加站点（域名或 `IP:端口`，PHP **7.4+**，不勾选数据库）
2. 上传全部文件到站点根目录（或服务器上 `git clone` 本仓库）
3. `data` 目录权限设为 **755/775**（确保 www 用户可写）
4. 若站点开了「防盗链/安全加固」，确认允许 `api.php` 的 POST 请求
5. 🔒 **确认 `data/` 目录无法通过 HTTP 访问**（这一步别跳过）
   - 仓库自带 `data/.htaccess`，**Apache** 站点自动生效
   - **nginx 站点 `.htaccess` 完全无效**，必须在站点配置里手动加：
     ```nginx
     location ^~ /data/ { deny all; return 404; }
     ```
   - **验证方法**：浏览器访问 `你的域名/data/admin_key.txt`，必须返回 **403 或 404**。
     如果能下载到内容，说明管理密码已经公网泄露 —— 立即加规则，并轮换密码
     （`echo '新密码' > data/admin_key.txt`）。
     `data/stories.json` 同理，它含每篇故事的删除凭证 `editKey`。
6. 访问站点即可。想清空数据重来：删除 `data/stories.json`（保留 seed.json）即可重置

### 方式二：Docker

#### 一键部署（Windows 本机）

项目根目录提供 `一键部署.bat`（双击运行），自动完成：本地打包（自动排除 stories.json 等运行时数据与密钥）→ 上传 → 远程解压重建 → 接口验证。

- **通道一（推荐，免密）**：阿里云 Workbench CLI。首次使用需准备：
  ```powershell
  # 安装（管理员 PowerShell）：irm https://workbench-cli.oss-cn-hangzhou.aliyuncs.com/install.ps1 | iex
  workbench config   # 登录阿里云账号（浏览器授权）
  workbench list     # 拿到 ECS 实例 ID（i-xxxx），填进 bat 顶部 INSTANCE_ID=
  ```
- **通道二**：Windows 内置 ssh/scp（注意：若服务器 sshd 关闭了密码登录则此通道不可用）

脚本顶部配置区可改：实例 ID、服务器 IP、远程目录、站点端口。

#### 手动部署

```bash
git clone https://github.com/Bhands6/dating-stories.git
cd dating-stories
docker compose up -d --build
# 访问 http://服务器IP:8010（端口在 docker-compose.yml 里改）
```

> 拉取 php:8.2-apache 镜像慢的话，先给 Docker 配国内镜像加速（例如：docker pull docker.m.daocloud.io/library/php:8.2-apache && docker tag docker.m.daocloud.io/library/php:8.2-apache php:8.2-apache）。

**镜像内置保障（2026-09-26 起）：**
- 生产级 PHP 配置（`display_errors=Off`）：运行时 Warning 不会混进 JSON 响应导致前端报 `Unexpected token '<'`
- 启动时自动把挂载的 `./data` 属主修正为 `www-data`（宿主机目录属主不符导致的写入失败自动修复）
- 种子兜底：宿主机 `./data` 为空时，首次运行自动用 `data/seed.json` 初始化站点
- 🔒 **禁止 HTTP 访问 `/data/` 目录**（2026-09-28 起）：镜像内 `deny-data.conf` 对 `/var/www/html/data` 施加 `Require all denied`，
  防止管理密码、全站数据库与删除凭证被当静态资源下载。部署后请用
  `curl -o /dev/null -w '%{http_code}' http://你的地址/data/admin_key.txt` 验证返回 **403**。

**管理页密码（admin_key.txt）：**
- 容器**首次启动自动生成 12 位随机密码**，写入 `data/admin_key.txt`，并在 `docker logs yuanfen-stories` 里打印一次
- `一键部署.bat` 的验证段**不再回显密码**（只提示 `ADMIN-PASSWORD-OK see data/admin_key.txt`）；查看请登录服务器 `cat data/admin_key.txt`
- 手动修改：`echo '新密码' > data/admin_key.txt`（改文件立即生效，无需重启）
- 🔒 **代码里已没有任何兜底默认密码**（v1.2 起移除，原先公开仓库里可见的 `yuanfen2025` 已删除）。
  文件缺失时会自动生成随机密码并落盘 —— 忘记配置不会导致「没有密码」，但也不要指望有已知默认值可猜

**接口返回非 JSON 排查（报错含 `<br />` 或 HTML 标签）：**

```bash
# 1) 看接口原始输出（应是一段以 {"ok": 开头的纯 JSON）
curl "http://127.0.0.1:8010/api.php?route=story&id=1&count=0"
# 2) 确认服务器代码版本为最新
git log --oneline -1
# 3) 确认 data 目录容器内可写（新版镜像启动时会自动修正，无需手动处理；旧镜像请手动执行）
chmod -R 777 data
# 4) 重新构建并重启
docker compose up -d --build
```

| 文件 | 内容 | 备份策略 |
|------|------|----------|
| `data/stories.json` | 故事/评论/点赞/删除凭证 | ⭐ 核心数据，定期下载备份 |
| `data/feedback.json` | 网友反馈 | 建议一并备份 |

| `data/rate_guard.json` | 写接口限流记录 | 可不备份（删掉即清零所有 IP 的额度） |
| `data/views_log.json` | 浏览量防刷记录 | 可不备份（自动过期清理） |

  一旦暴露就等于全站失守——Apache 靠仓库自带的 `data/.htaccess`，nginx 必须自己写 `location ^~ /data/ { deny all; }`

## 📖 API 一览

统一入口 `api.php?route=xxx`（本地 Node 服务器同路径同参数）：

| route | 方法 | 参数 | 说明 |
|-------|------|------|------|
| stories | GET | filter=hot/new/13 分类, page, limit | 故事列表（热门按 点赞×3+评论×5+浏览×0.5） |
| stories | POST | {title, content, mode, tags, nickname} | 发布故事，返回一次性 editKey 删除凭证（限流：10 分钟 5 篇） |
| story | GET | id, count | 详情；count=0 不计数（配合 IP 24h 去重） |
| raw | GET | id | 故事原文（HTML 沙箱渲染 / 纯文本排版），CSP 沙箱头 |
| like | POST | {id, undo} | 点赞 / 取消 |
| comments | GET / POST | id; {nickname, content, replyTo?} | 评论列表 / 发表；replyTo 传目标评论或回复的 id 即为楼中楼回复（两级结构：回复统一挂其所属一级评论 replies 下并记录被回复人昵称），评论数=一级评论+回复（真实互动量，不含模拟基数）。发表限流：5 分钟 15 条 |
| delete_story | POST | {id, editKey} | 发布者凭凭证删除自己的故事 |
| tags | GET | — | 13 分类计数（标签云） |
| stats | GET | — | 站点统计 |
| hot | GET | limit | 热门精选 TOP N（按 点赞×3+评论×5+浏览×0.5 排序，全时段） |
| feedback | POST | {nickname, contact, content} | 网友提交反馈（限流：30 分钟 3 条） |
| admin_feedback | POST | {key, op: list/delete/read, id, ids?, page, pageSize} | 管理：反馈查看/删除/标记已读（`op=read` 不传 `ids` 则全部标为已读，返回 `marked` 计数；密码错误累计 5 次返回 429 锁定 15 分钟）；列表分页，默认每页 20、上限 100 |
| admin_stories | POST | {key, op: list/delete/update, id, ids?, tag, q, sort, page, pageSize} | 管理：故事列表（最新在前、标签筛选、`q` 搜索、`sort` 排序、分页）/编辑（只改标题·正文·标签，点赞评论浏览凭证均保留）/删除（`ids` 数组可批量，单篇仍用 `id`；同上限流） |
| admin_comments | POST | {key, op: list/delete, storyId?, q, commentId, page, pageSize} | 管理：评论时间线（`storyId` 只看某篇故事的评论）/删除（删一级评论连带其 `replies`） |
| admin_stats | POST | {key} | 管理：数据概览（故事/赞/浏览/评论总数、今日新增、未读反馈数） |
| admin_export | POST | {key, what: stories/feedback} | 管理：导出 JSON 文件（带 `Content-Disposition`） |
| admin_change_key | POST | {key, newKey} | 管理：修改管理密码（先验旧密码，新密码 8~64 位） |

**写接口限流**（按 IP 滑动窗口，超限返回 `429` + 友好提示，记录在 `data/rate_guard.json`）：

| 动作 | 上限 | 窗口 | 提示 |
|------|------|------|------|
| 发布故事 | 5 篇 | 10 分钟 | 发布太频繁啦，请 N 分钟后再试 💕 |
| 评论 / 回复 | 15 条 | 5 分钟 | 评论太频繁啦，请 N 分钟后再试 💕 |
| 提交反馈 | 3 条 | 30 分钟 | 提交反馈太频繁啦，请 N 分钟后再试 💕 |

> - 阈值刻意留得宽松，正常用户基本碰不到；**校验不通过的提交不消耗额度**（填错重试不会被罚）。
> - 调整阈值：改 `api.php` 的 `RATE_LIMITS` 与 `server.js` 的 `RATE_LIMITS`，**两边必须一致**。
> - 误伤了解封：删除服务器上的 `data/rate_guard.json` 即可（立即对所有 IP 清零）。
> - 记录不可写时**自动放行**——限流是附加保护，不能因为写不了日志就把正常用户挡在门外。
> - 清理过期记录时按**各自动作自己的窗口**判过期（发布 600s / 评论 300s / 反馈 1800s），不会互相误删。

## ❓ 常见问题

**Q：改了代码/样式，浏览器显示没变化？**
浏览器缓存了旧页面，按 `Ctrl + F5` 强制刷新。（服务端已禁用 HTML/JS 缓存，正常刷新也应拿到新版）

**Q：管理页进不去/提示密码错误？**
确认访问地址是 `域名/admin.html`；密码在服务器 `data/admin_key.txt` 文件里（自动生成的随机密码）。忘了就上服务器：`cat data/admin_key.txt` 查看，或 `rm data/admin_key.txt` 后重启容器重新生成。
若提示「**密码错误次数过多**」，说明触发了登录限流（同 IP 连错 5 次锁 15 分钟）——等 15 分钟，或删除 `data/admin_guard.json` 立即解锁。

**Q：一键部署.bat 报 `bad flag syntax` 或 `Unexpected token '<'`？**
前者是旧版脚本的引号嵌套问题，后者是旧镜像缺生产级 PHP 配置——都用最新版 `一键部署.bat`（内部 tar 打包走白名单排除、容器走生产级 php.ini）重新跑一遍即可。基础镜像拉不动时先配国内加速：`docker pull docker.m.daocloud.io/library/php:8.2-apache && docker tag docker.m.daocloud.io/library/php:8.2-apache php:8.2-apache`。

**Q：想清空所有数据重新开始？**
删除服务器上的 `data/stories.json` 和 `data/feedback.json`（保留 `seed.json`），刷新即自动重置为示例内容。

**Q：上传的 HTML 故事样式不对/显示不全？**
请用「📄 上传 HTML 文件」方式导入（不要只复制纯文本），发布后通过弹窗里「📖 原文阅读」查看原样式效果。仍异常的话，检查文件里的 CSS 是否写在了 `<link>` 外链（外链样式不会随文件带入）。

**Q：发布后自动弹出的故事，刷新主页又弹？**
已修复：关闭弹窗时会自动清掉地址栏的一次性参数。若仍复现，确认部署的是最新版 `index.html`。

**Q：端口被占用？**
本地 `node server.js` 会自动从 8000 起尝试 +1；服务器端口在 `docker-compose.yml`（Docker）或宝塔站点设置（PHP）里改。

**Q：故事/评论能删吗？**
发布者：详情弹窗里「🗑 删除我的故事」（凭发布时自动保存的凭证，换浏览器/清缓存后凭证失效）。站长：管理页可删除任意故事和反馈。

  发布额度就被重置。现按各自动作自己的窗口判过期

**v1.2（2026-09-28）**
- ⚠️ **严重：封堵 `/data/` 目录的公网访问**。此前 Apache 会把 `data/` 当静态资源直接返回，
  任何人访问 `站点/data/admin_key.txt` 即可拿到管理密码，`站点/data/stories.json` 可拿到
  全站数据库**及每篇故事的删除凭证 `editKey`**（等于可以删任意人的故事）。

- 安全：移除 `Access-Control-Allow-Origin: *`——站点为同源部署，不再允许第三方站点跨域调用管理接口
- 安全：管理接口新增登录限流，同 IP 连续输错 5 次锁定 15 分钟（返回 429），记录存 `data/admin_guard.json`
- 安全：**删除公开仓库中可见的兜底密码**，`admin_key.txt` 缺失时自动生成随机密码（PHP 与 Node 行为一致）
