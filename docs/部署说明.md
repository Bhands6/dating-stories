# 人生故事屋 🏠

一个**零数据库依赖**的匿名人生故事分享社区。Node.js 零依赖后端 + 纯前端页面 + JSON 文件存储，2 核 2G 服务器轻松运行。

- **技术栈**：Node.js 22（生产与本地**同一份** `server.js`）· 纯 HTML/CSS/JS 前端 · JSON 文件存储
- **无需**：MySQL、npm 依赖、构建工具、用户注册系统
- **历史**：2026-11-06 前 `api.php`（PHP）为生产后端、`server.js` 仅本地开发；现已统一为 Node，`api.php` 退役（git 历史可查）

## ✨ 功能特性

**前台（访客）**
- 故事广场：热门/最新 + 7 个频道筛选（爱情/日常/搞笑/职场/家庭/成长/吐槽），分页加载
- 详情弹窗：点赞（本地记忆防连点）、匿名评论、评论回复（两级楼中楼，「回复 @昵称」标注；≥3 条回复默认折叠可展开/收起；发评论/回复局部刷新不跳顶并定位高亮新内容）
- **评论表情与配图**：输入框下方「😊」展开表情面板（48 个常用 emoji，内嵌展开不遮挡输入），
  「📷」选图或直接 **Ctrl+V 粘贴**；评论/回复各带 1 张图（≤2MB，前端压到长边 1200px 并剥 EXIF），
  也支持「只发一张图不写字」；点评论里的图可看原图
- **删除自己的评论/回复**：评论成功时下发删除凭证（仅存评论者本机），列表里只有自己发的评论才出现「删除」；删一级评论会连带删掉它的全部回复，删除前有站内确认弹窗
- HTML 排版故事：**上传的原始文件原样存档**（`data/uploads/{id}.html`，未净化、不受 5 万字符限制），
  沙箱 iframe 渲染 + 「原文阅读」新窗口打开，样式 100% 原样；Google Fonts 字体经**站内代理**加载，
  国内不翻墙也能正常显示站酷小薇、志莽行书这类网络字体
- 浏览量防刷：按「浏览器 visitorId + 故事」去重（12 小时窗口），同 IP 另有次数上限兜底
- 频道云（实时计数）、站点统计、关于与合规页面（内容规范/隐私声明/免责声明）

**发布（匿名，无需登录）**
- 7 个频道单选（默认「日常分享」）
- 纯文本 / HTML 双模式编辑；HTML 支持上传本地文件（**原件随发布一起存档，阅读时原样还原**）+ 富文本粘贴（外链样式表自动转 `@import` 保留）
- **插图**：工具栏「📷 图片」选图，或直接在编辑区 **Ctrl+V 粘贴**（截图、网页图片都行）。
  前端压缩到长边 ≤1600px（JPEG 0.82，GIF 保留动画），canvas 重编码同时**剥掉 EXIF**（避免带出 GPS 定位）；
  正文里以 `【图N】` 占位，发布时随 `images` 数组提交，渲染时替换成图片。
  **纯文本模式实际是一个 contenteditable 富文本编辑区**：textarea 无法显示图片，所以 `【图N】`
  在编辑时就地画成一张缩略图卡片（64px 小图 + 「图N」角标 + ✕），卡片 `contenteditable=false`
  可以整体选中或用 Backspace 删除。textarea 仍作为纯文本数据源保留 `【图N】`，发布 / 预览都读它，
  **后端与 payload 零改动**；rich 输入实时序列化回 textarea，程序改 textarea 时反向重建 rich（打字时不重建，避免丢光标）。
  卡片上的 ✕ 或删除卡片后，该图会落到下方「未插入正文的图片」回收条，点一下可插回光标处；
  `images` 数组只增不减（删中间项会让 `【图3】` 指向错图）。
  HTML 模式仍用原来的 textarea 写代码，编辑区自动切换；点「👁️ 预览」时纯文本模式把 `【图N】` 渲染成真实图片（圆角 + 淡边框）
- **手机照片**：iPhone/安卓原图通常 3~10MB（4000×3000），压缩在**浏览器里完成**，
  传到服务器的只有 150~500KB，所以不会撞上「单图 2MB」的限制；压完仍偏大时会自动降到 1200px / 0.75 再试一次。
  原图超过 30MB 或 HEIC 格式会给出明确提示（HEIC 浏览器解不了，需从相册选择让它转成 JPG）
- **AI 排版引导弹窗**：切到 HTML 模式自动弹出三步指引 + 可一键复制的提示词模板 + DeepSeek/豆包/小米 MiMo 官网直达（可勾选不再提示）
- 发布后自动跳转预览自己的故事；随机匿名昵称
- 发布者获得删除凭证，可随时删除自己的故事

**站长管理（`/admin.html`，密码保护）**
- 📮 反馈箱：查看/删除网友反馈（含联系方式）
- 📚 故事管理：最新/点赞/浏览/评论/热度排序、频道筛选、关键词搜索、分页、点击预览（沙箱弹窗）、
  编辑（**有原始文件的故事会先弹警告**，避免误删原件）、批量删除、置顶、行内查看评论
- 🔗 友情链接：名称 + 跳转链接 + 图标（可直接上传 PNG/JPG/GIF/WEBP，≤300KB），支持排序、增删，
  保存后首页页脚即时生效，**不用再改代码**
- 🔑 密码为容器首次启动自动生成的 12 位随机密码（`data/admin_key.txt`），可随时手动修改

**内置安全**
- 内容净化：去 script/事件属性/危险协议/CSS 表达式
- 样式隔离：HTML 故事以沙箱 iframe + CSP 沙箱头渲染，与站点完全隔离
- **原始文件模式**：上传的原件不做净化（保留作者的 script），但单独收紧 CSP ——
  `connect-src 'none'`（禁 fetch/XHR/WebSocket）、`form-action 'none'`、`base-uri 'none'`；
  脚本仍跑在不透明源里，读不到站点 cookie/localStorage、发不出网络请求、无法提交表单
- 管理接口：密码校验（自动生成、无默认值）+ 同 IP 连续失败 5 次锁定 15 分钟
- 写接口限流：按 IP 滑动窗口限制发布/评论/反馈/删评/删故事（超限 `429`），防脚本刷屏与凭证爆破
- 跨域：接口不返回 `Access-Control-Allow-Origin`，站点为同源部署，第三方站点无法在浏览器里跨域调用管理接口
- 客户端 IP：**默认不信任 `X-Forwarded-For`**。本站前面没有反代，该头可由客户端伪造，
  信任它会让限流和浏览量去重被一个请求头绕过；将来挂了 nginx/CDN 再把
  `server.js` 的 `TRUST_FORWARDED_FOR` 改成 `true`
- 评论/反馈长度限制；发布者删除凭证（随机 editKey）
- 数据一致性：所有写盘走「临时文件 + `rename` 原子替换」，进程中断不会留下残缺 JSON；
  互斥用**独立的 `.lock` 文件**（`flock` 锁的是 inode，`rename` 之后锁会失效，所以不能直接锁数据文件）；
  「读-改-写」全程持锁，并发下不会丢更新

## 🚀 部署

> **字体代理的网络要求**：`route=font` 由**服务器**去抓 `fonts.googleapis.com` / `fonts.gstatic.com`。
> 服务器能出网时，站酷小薇、志莽行书这类网络字体正常显示；出不去时会安静降级本机/系统字体，
> **站点其它功能完全不受影响**（`route=font` 失败只返回 404，浏览器自动回落）。
> 国内机房能否直连 Google 因厂商与区域而异，部署后可用
> `curl -s -o /dev/null -w '%{http_code}' https://fonts.googleapis.com/css2?family=Noto+Serif+SC` 自测。

### 🔑 管理页密码（无需改代码）

管理页 `admin.html` 的密码**不再需要改代码，也没有任何默认密码**：

- **Docker**：容器首次启动时自动生成一个 **12 位随机密码**，写入 `data/admin_key.txt` 并在 `docker logs yuanfen-stories` 里打印一次。
  > 出于安全考虑，`一键部署.bat` 的验证段**不再回显密码**（只提示 `ADMIN-PASSWORD-OK see data/admin_key.txt`）。
  > 需要查看时登录服务器执行 `cat data/admin_key.txt`。
- **宝塔 / 手动 Node**：**首次调用管理接口时自动生成**同样的随机密码并写入 `data/admin_key.txt`（server.js 内置，无需启动钩子）。
- 手动修改：`echo '新密码' > data/admin_key.txt`（改文件立即生效，无需重启）
- ⚠️ 该文件是唯一的管理入口，请妥善保存；已加入 `.gitignore`，切勿提交进仓库

**登录限流**：同一 IP 连续输错 **5 次**密码即锁定 **15 分钟**（返回 `429`），期间即使密码正确也会被拒。防脚本暴力猜密码用；记录写在 `data/admin_guard.json`，删除该文件即可立即解锁。

### 方式一：宝塔面板（推荐，最简单）

> ⚠️ **v1.16 起后端是 Node**，宝塔纯 PHP 建站不再适用。宝塔下可用「Node 项目」或
> PM2 守护 `node server.js`（`PORT=80` 或反代到它）；更推荐直接用下面的 Docker 方式。
1. 上传全部文件到站点目录（或服务器上 `git clone` 本仓库）
2. `data` 目录权限设为 **755/775**（确保运行用户可写）
3. 🔒 **确认 `data/` 目录无法通过 HTTP 访问**（这一步别跳过）
5. 🔒 **确认 `data/` 目录无法通过 HTTP 访问**（这一步别跳过）
   - 仓库自带 `data/.htaccess`，**Apache** 站点自动生效
   - **nginx 站点 `.htaccess` 完全无效**，必须在站点配置里手动加：
     ```nginx
     location ^~ /data/ { deny all; return 404; }
     ```
   - **验证方法**：浏览器访问 `你的域名/data/admin_key.txt`，必须返回 **403 或 404**。
     如果能下载到内容，说明管理密码已经公网泄露 —— 立即加规则，并轮换密码
     （`echo '新密码' > data/admin_key.txt`）。
     `data/stories.json` 同理，它含每篇故事的删除凭证 `editKey`。
6. 访问站点即可。想清空数据重来：删除 `data/stories.json`（保留 seed.json）即可重置

### 方式二：Docker

#### 一键部署（Windows 本机）

项目根目录提供 `一键部署.bat`（双击运行），自动完成：本地打包（自动排除 stories.json 等运行时数据与密钥）→ 上传 → 远程解压重建 → 接口验证。

- **通道一（推荐，免密）**：阿里云 Workbench CLI。首次使用需准备：
  ```powershell
  # 安装（管理员 PowerShell）：irm https://workbench-cli.oss-cn-hangzhou.aliyuncs.com/install.ps1 | iex
  workbench config   # 登录阿里云账号（浏览器授权）
  workbench list     # 拿到 ECS 实例 ID（i-xxxx），填进 bat 顶部 INSTANCE_ID=
  ```
- **通道二**：Windows 内置 ssh/scp（注意：若服务器 sshd 关闭了密码登录则此通道不可用）

脚本顶部配置区可改：实例 ID、服务器 IP、远程目录、站点端口。

#### 手动部署

```bash
git clone https://github.com/Bhands6/dating-stories.git
cd dating-stories
docker compose up -d --build
# 访问 http://服务器IP:8010（端口在 docker-compose.yml 里改）
```

> 拉取 node:22-alpine 镜像慢的话，先给 Docker 配国内镜像加速（例如：docker pull docker.m.daocloud.io/library/node:22-alpine && docker tag docker.m.daocloud.io/library/node:22-alpine node:22-alpine）。

**镜像内置保障（2026-11-06 起，Node 化后）：**
- **零依赖**：`server.js` 只用 Node 内置模块，镜像里没有 `npm install` 步骤，构建快、体积小
- 前端所有页面仍请求 `/api.php?route=xxx`，由 `server.js` 原样接住（历史路径不变，书签/缓存都不受影响）
- HTML/CSS/JS 响应头 `Cache-Control: no-cache`（旧 Apache 的 no-cache.conf 等价能力在 `serveStatic` 里实现）
- 种子兜底：宿主机 `./data` 为空时，首次运行自动用 `data/seed.json` 初始化站点
- 🔒 **禁止 HTTP 访问 `/data/` 目录**：`server.js` 的 `serveStatic` 对 `data/` 一律 **403**（与旧 Apache `deny-data.conf` 等价），
  防止管理密码、全站数据库与删除凭证被当静态资源下载。部署后请用
  `curl -o /dev/null -w '%{http_code}' http://你的地址/data/admin_key.txt` 验证返回 **403**。
- 目录穿越防护：`path.normalize` + 前缀校验，`/uploads/../admin_key.txt` 这类路径一律 **403/404**

**原文阅读：静态直出上传的原始 HTML（2026-10-30 起；Node 化后由 `server.js` 的 `serveUploadSource` 实现）**
- `/uploads/{id}.html` 由 `server.js` 直接读 `data/uploads/{id}.html` 吐出（无需额外挂载）：
  **零加工、字节级原件**，不加字体垫片、不改任何标签、不注入脚本。
- 响应头仍带 `Content-Security-Policy: sandbox allow-scripts; connect-src 'none'; form-action 'none'; base-uri 'none'`，
  文档是不透明源 —— 访客上传的 HTML 读不到站点 cookie/localStorage、调不到同源接口。
  ⚠️ **这个头绝不能删**，否则等于把网友上传的 HTML 放到同源下执行。
- 前端 `index.html` 按 `hasSource` 决定：有源文件 → `/uploads/{id}.html`；早期没有源文件的存量故事 → 回落 `raw` 路由（净化版 + 字体垫片）。
- 详情弹窗里的 iframe 走 `raw&theme=<当前主题>`，并给了一个「🌙 跟随主题 / ☀️ 原始亮度」开关（记在 `localStorage.yst-story-follow`）：
  跟随主题时服务端只在 `<head>` **最前面**注一段低优先级样式（底色 / 文字色 / 滚动条），作者自己的 CSS 随后就能盖住它；
  深色主题再对整页套 `filter: brightness(.62) saturate(.92)`。
- ⚠️ 为什么不是"真的改成深底浅字"：这些 HTML 故事是整屏渐变／海报式设计，靠改 CSS 变量只会把设计稿毁掉
  （实测把 `--bg/--text` 换掉后封面毫不变、正文反而花）。压暗是唯一**既能明显看出变化、又不破坏版式**的做法。
- ⚠️ 开关**只在深色主题（code）下显示**：浅色三主题里"跟随"和"原样"本来就没差别，摆出来只会让人以为坏了。
- 「原文阅读」不带 `theme`，看到的是字节级原件。
- ⚠️ 因为不再加字体垫片，**原文阅读页里 Google Fonts 拉不到，字体会退回系统宋体/雅黑**（原本的设计观感会略降）。
  这是「字节级原件」的代价；详情页弹窗走的仍是 `raw`（带垫片），观感不变。
- 部署后自检：
  `curl -s -D - -o /dev/null http://127.0.0.1:8010/uploads/61.html | grep -i "content-security-policy"` 应有输出；
  `curl -o /dev/null -w '%{http_code}' http://127.0.0.1:8010/uploads/../admin_key.txt` 应为 **403/404**。

## 🎨 主题系统（2026-10-22，全站）

站点带四套界面主题，右上角菜单或 `Alt + 1~4` 切换，选择存在浏览器 `localStorage['yst-theme']`：

| key | 名称 | 说明 |
|-----|------|------|

| `word` | 摸鱼 · 文档 | Word 风：宋体正文 + 黑体标题 + 白纸页 + 伪装成 `季度工作总结.docx` |

**实现结构（两个共享文件，7 个页面全部引用）**：

```
<head>
    <link rel="stylesheet" href="theme.css">   ← 变量 + 四套主题 + 切换器样式
    <script src="theme.js"></script>           ← 防闪 + 注入切换器 + 标题/图标伪装 + 快捷键
```

- `theme.css` 的 `:root` 是**唯一**的配色来源，`html[data-theme="excel|code|word"]` 只做变量覆盖
- `theme.js` 在 head 同步执行，首屏前就把 `data-theme` 挂到 `<html>`（否则刷新会先闪一下粉色），
  并自动往 `.nav-inner` 末尾注入切换器——**各页不需要写任何主题相关的 HTML**
- 三套摸鱼主题会隐藏飘心与背景装饰、收敛圆角、把彩色标签/头像/角标扁平化，
  关掉悬浮位移（太"网页"）

> ⚠️ **维护铁律**：页面里新增颜色必须走变量（`--primary-rgb` / `--surface*` / `--on-primary` / `--danger-*` / `--font-body` …）。
> 写死 `#hex`、`rgba(232,85,109,…)` 或 `background:white` 只会在切主题时漏色，而且**不报错**，
> 只能靠四套主题逐页肉眼翻。
>
> ⚠️ 访客 HTML 的容器（`.story-iframe` / `.view-frame`）**故意保持白底**：里面是别人自己的页面，
> 深色主题下也要保证正文可读，不要跟着变量走。
>
> ⚠️ `theme.css` / `theme.js` 必须写进 `Dockerfile` 的 COPY 白名单，否则镜像里缺文件，全站变裸样式。

## 🔐 Node 运行时升级与安全补丁

后端运行时是 **Node.js 22**（`Dockerfile` 的 `FROM node:22-alpine`）。Node 只解释我们自己的
`server.js`，不像 PHP 那样在应用代码之前有大量内置 Web 攻击面（如曾经的 php2shell），
但 Node 运行时自身的 CVE 仍需跟随：补丁只存在于新的基础镜像里，**不会随 `git pull` 进来**。

### ⚠️ 最容易踩的坑：`--build` 不等于 `--pull`

docker build **优先命中本地同名 tag**，本机已有的 `node:22-alpine` 会一直被复用，于是：

```bash
docker compose up -d --build   # ❌ 只重建代码层，Node 版本纹丝不动
```

必须显式拉新基础镜像：

```bash
docker compose build --pull    # ✅ 走镜像加速拉最新基础镜像
docker compose up -d
```

### 标准升级流程

```bash
cd /home/Bhands_StoryBase

# 1) 备份数据（25M，几秒）
cp -a data data.bak-$(date +%Y%m%d)

# 2) 验证新基础镜像确实是新版（镜像加速站可能滞后）
docker pull docker.m.daocloud.io/library/node:22-alpine
docker run --rm docker.m.daocloud.io/library/node:22-alpine node -v

# 3) 记下当前镜像 ID（回滚用，build 会清掉旧完整镜像）
docker images | grep node

# 4) 重建并重启
docker compose build --pull
docker compose up -d

# 5) 验证
docker exec yuanfen-stories node -v
curl -s -o /dev/null -w 'index:%{http_code}\n' http://127.0.0.1:8010/
curl -s 'http://127.0.0.1:8010/api.php?route=stats'
```

预期停机 **5~10 秒**（容器 Recreate）。`data/` 挂在宿主机 `./data` 卷上，重建容器不碰数据。

### 回滚

```bash

docker compose up -d
```

## 💾 数据与备份

ZIP 是请求时即时生成的，**不会在服务器落盘**，所以不占磁盘、也不需要加进 `.gitignore`。

| 文件 | 内容 | 备份策略 |

| `data/friends.json` | 友情链接配置（首页页脚） | 建议备份（丢了会退回内置默认友链）；不进仓库 |

| 上传插图 | 100 张 | 1 小时 | 上传图片太频繁啦，请 N 分钟后再试 💕 |
| 完整备份 | 20 次 | 1 小时 | 完整备份太频繁啦，请 N 分钟后再试 💕 |

> - 阈值刻意留得宽松，正常用户基本碰不到；**校验不通过的提交不消耗额度**（填错重试不会被罚）。
> - 调整阈值：改 `server.js` 的 `RATE_LIMITS`。
> - 误伤了解封：删除服务器上的 `data/rate_guard.json` 即可（立即对所有 IP 清零）。
> - 记录不可写时**自动放行**——限流是附加保护，不能因为写不了日志就把正常用户挡在门外。
> - 清理过期记录时按**各自动作自己的窗口**判过期（发布 600s / 评论 300s / 反馈 1800s / 删评·删故事 600s），不会互相误删。

## ❓ 常见问题

**Q：改了代码/样式，浏览器显示没变化？**
HTML 页面已设 `Cache-Control: no-cache`，正常刷新就会拿到新版。若仍是旧版，说明浏览器用了内存缓存：
按 `Ctrl + Shift + R` 硬刷新，或直接开**无痕窗口**验证（无痕没有历史缓存，最可靠）。
`publish.html` 源码里留了 `<!-- build: 日期 版本 -->` 注释，右键「查看网页源代码」可确认拿到的是哪一版。

**Q：管理页进不去/提示密码错误？**
确认访问地址是 `域名/admin.html`；密码在服务器 `data/admin_key.txt` 文件里（自动生成的随机密码）。忘了就上服务器：`cat data/admin_key.txt` 查看，或 `rm data/admin_key.txt` 后重启容器重新生成。
若提示「**密码错误次数过多**」，说明触发了登录限流（同 IP 连错 5 次锁 15 分钟）——等 15 分钟，或删除 `data/admin_guard.json` 立即解锁。

**Q：一键部署.bat 报 `bad flag syntax` 或 `Unexpected token '<'`？**
前者是旧版脚本的引号嵌套问题，后者是旧镜像缺生产级 PHP 配置——都用最新版 `一键部署.bat`（内部 tar 打包走白名单排除、容器走生产级 php.ini）重新跑一遍即可。基础镜像拉不动时先配国内加速：`docker pull docker.m.daocloud.io/library/php:8.2-apache && docker tag docker.m.daocloud.io/library/php:8.2-apache php:8.2-apache`。

**Q：想清空所有数据重新开始？**
删除服务器上的 `data/stories.json` 和 `data/feedback.json`（保留 `seed.json`），刷新即自动重置为示例内容。
⚠️ 原件存档在 `data/uploads/` 里，删 `stories.json` 后这些文件会变成孤儿，建议一并清空
（`rm -rf data/uploads/*`）；`data/fontcache/` 可以随便删，会自动重建。

**Q：上传的 HTML 故事样式不对/显示不全？**
请用「📄 上传 HTML 文件」方式导入（不要只复制纯文本），发布后通过弹窗里「📖 原文阅读」查看原样式效果。
`<link rel="stylesheet">` 会自动转成 `@import` 保留，外链样式表可以照常生效。

想**完全原样**（保留 `<script>`、注释、原始 DOM），上传文件后直接发布即可 ——
看到提示「**原文件已原样保存**」就说明走的是原件模式，`原文阅读` 会直接输出你上传的那个文件。

**Q：上传的 HTML 和本地直接打开不完全一样？**
先看发布成功时的提示：

- **「原文件已原样保存」** → 原件模式，`原文阅读` 直接输出你上传的文件，内容应当 100% 一致。
  若仍有差异，多半是字体还在下载（首次约 100-200ms，`font-display: swap` 会先显示回退字体）
- **只有「发布成功」** → 走的是净化模式（原件没提交成功，常见于浏览器缓存了旧版发布页）

另外系统有一个**结构容错**：若 CSS 写了 `.hero h1 { font-family: ... }`，但 HTML 里没有 `.hero` 元素
（AI 生成的单文件 HTML 常见这种「样式按 `.hero` 写、结构却是 `.wrap`」的错位），
会自动把字体规则补到 `h1` / `.hand` 上，避免标题静默退回系统字体。
它**只补 `font-family`**，不动 padding、对齐等布局属性。

**Q：上传的文件打开是乱码？**
文件不是 UTF-8 编码（国内常见 GBK / ANSI 存法）。用记事本「另存为」把编码选成 **UTF-8** 再上传。
发布页检测到乱码会直接拦下并提示，不会让乱码内容发出去。

**Q：管理页改了正文，原文阅读却没变（或变成普通排版）？**
带「📄 原件」徽章的故事，`原文阅读` 读的是 `data/uploads/{id}.html` 原件。
编辑正文并保存会**删除原件**（保存前会弹确认框），此后统一显示编辑后的内容。
只改标题不会动原件。想要回原件模式，重新上传一次文件即可。

**Q：字体和本地打开时不一样？**
分三层处理：
1. 正文里用到的 Google Fonts 字体会被自动生成 `<link>`，经 `route=font` 走**站内代理**加载
   （服务端抓取并缓存，浏览器不直连 Google，国内可达）。代理失败时安静回落到第 2、3 层
2. 字体兼容垫片用 `@font-face` + `local()` 把常见字体名映射到本机等价字体
   （Noto Serif SC→思源宋体/宋体、ZCOOL XiaoWei→思源宋体、书法体→华文行楷等）
3. 最后回落到作者写的 `serif` / `sans-serif`

所以仍有差异的多半是**本机装了某种字体、但浏览器还没下载完代理字体**，强刷一次即可。
若某字体在 Google Fonts 上不存在（如商业字体），只能由作者把字体子集化后以 base64 内嵌。

**Q：发布后自动弹出的故事，刷新主页又弹？**
已修复：关闭弹窗时会自动清掉地址栏的一次性参数。若仍复现，确认部署的是最新版 `index.html`。

**Q：端口被占用？**
本地 `node server.js` 会自动从 8000 起尝试 +1；服务器端口在 `docker-compose.yml`（Docker）或宝塔站点设置（PHP）里改。

**Q：故事/评论能删吗？**
发布者：详情弹窗里「🗑 删除我的故事」（凭发布时自动保存的凭证，换浏览器/清缓存后凭证失效）。站长：管理页可删除任意故事和反馈。
删除故事时，它在 `data/uploads/` 里的原始 HTML 文件会一并清理，不会留下孤儿文件。
