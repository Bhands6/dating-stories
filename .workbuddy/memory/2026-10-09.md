### 踩坑记录（重要，下次直接避开）
- **`id` 参数走 URL query，不走 body**：`api.php?route=delete_comment&id=43`，
  放 body 里会 404（`$id = parseInt(url.searchParams.get('id'))`）。测试时白折腾一轮
- `data/stories.json` **不在 git 里**（本地数据文件），`git checkout` 恢复不了 →
  测前必须手工 `cp -r data /tmp/backup`，测后拷回
- curl 在本机默认走代理，请求 localhost 会报 `upstream connect failed` → 必须加 `--noproxy '*'`
- 后台起服务要用 `run_in_background=true`，`cmd &` 起的进程会随命令结束被回收
- `/tmp/xxx` 在 Git Bash 下映射到 `F:\tmp`，node 写不进去，临时文件放项目目录再删

## 自查发现并修复的 5 个问题（14:31 用户要求「检查是否有不妥」）
功能本身能跑，但复查发现 5 处隐患，均已修 + 回归验证：

| # | 问题 | 影响 | 修复 |
|---|------|------|------|
| 1 | `deletions.json` 未进 .gitignore / .dockerignore / 部署脚本排除清单 | **隐私泄露**：文件含访客昵称+被删内容摘录，会进仓库/镜像/上传包 | 三处全部补排除 |
| 2 | 前端 `op=read` 丢弃服务端返回的新 `readUpTo`，仍用请求前的旧值 | 计数已归零但列表每条都渲染成未读高亮，**自相矛盾** | 改用 `r.readUpTo` |
| 3 | `loadDelCount` 与 `loadDeletions` 并发时互相覆盖 `delReadUpTo` | 水位可能被慢请求回退，未读数闪回 | 加 `delReqSeq` 序号丢弃过期响应 |
| 4 | PHP 用 `is_int()` 校验 `nextId`/`readUpTo` | JSON 数字解出 float（`4.0`）时判定非法 → **nextId 被重置=1，id 复用** | 改 `is_numeric()`（4 处） |
| 5 | `record_deletion` 拿不到锁时带 null 继续读改写 | 无锁并发写可能覆盖数据/写坏文件 | 拿不到锁直接 return |

另修 1 个 UX：后端最多返回 100 条，界面显示「共 200 条」却不告知截断 → 补「仅显示最近 N 条」。

追加记录，正确推进到 5（未重置），ids 无复用。
⚠️ JS 侧用 `Number.isInteger` 无此问题（JS 里 `4.0 === 4`），两侧语义等价，只改 PHP。
